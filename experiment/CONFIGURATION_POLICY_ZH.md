# 统一配置规则 configuration-defaults-v3

旧实验结果与配置保留，不覆盖原始数据集。最终接口专项报告位于 `experiment/output/contract_planning_v5_20261016/REPORT_ZH.md`；各开发轮次分别保留在 v2/v3/v4/v5 目录，不与 v1 全量实验混合计分。配置策略当前为 v3，接口验证轮次编号独立于配置版本。

## 接口规划修复

- 按钮 D2、D3、D4 和 D2/D3 等分组接线逐个保留；补齐风扇、继电器、水泵、反向传感器接线及 Trig/Echo 的“连接”写法，避免生成并不存在的第二个器件。
- 配置中的角色表明确为部分解析结果，不是排除其他源需求的白名单。现有显式接线继续有效；冲突重映射同时修改有效需求，并保留原文。
- `wiring_inventory.py` 从电路网络提取每个器件的 MCU 引脚、信号、供电与目录操作形状。条形灯 A1..A10 是器件端子，按实际段序映射到 MCU 引脚；RGB 可用逐通道标量请求，不再误报整个器件不可表达。
- 提案中 `device` 可标识源电路器件。唯一器件映射或唯一匹配引脚可以恢复已确认的接线与按钮有效电平、上拉；多实例歧义不猜测。验收还会检查器件对应的操作，不能仅靠覆盖同一组引脚过关。
- 条形灯支持实际已接线的连续4/6/8/10段；共享被动LED负载每个物理GPIO只注册一次，并保留共同信号的物理约束。共阳RGB从电源接线推导反向电气映射，而不是依赖模型猜测。
- 模拟/PWM 提案中无效果的 `active_high=true`、`pullup=false` 可移除并记录；有反相或上拉含义的取值仍拒绝。移位寄存器 `Q0`/`sr1:Q0` 可等价规范为位号 0，其他寄存器名称不自动替换。
- 重复 DHT 通道给出具体端口和修复指引，不静默删除导致 io_i 引用错位。缺少驱动、串口复杂协议、无输出目标等问题继续如实报告。

## 默认与重映射

- 已有合法且无冲突的引脚保持原样。未指定的引脚按固定候选顺序分配，跳过已声明和已占用的引脚，保留 D0/D1。
- 默认候选：TM1637 CLK/DIO 为 D4/D5，DHT 为 D7，HC-SR04 Trig/Echo 为 D8/D9，按钮为 D2、LED 为 D13、蜂鸣器为 D6。候选被占用时选择兼容的空闲引脚，而不是把两个接口强行绑定到同一引脚。
- PWM 优先保留兼容端点；同时考虑当前后端声明的蜂鸣器、舵机与 PWM 定时器限制。普通数字端点可以移动。
- 显式冲突可重映射。例如风扇 PWM D5 与 TM1637 DIO=D5 冲突时，保留 PWM，将 DIO 移到空闲数字引脚。决策记录包含原值、新值和原因。
- 已提供电路中的可识别冲突会输出修改后的电路副本。共用 I²C/SPI 信号和并联被动显示负载保留；新接线需要实际硬件或仿真电路采用相同映射。
- 串口缺省为 9600 baud、`line_or_idle` 分帧、20 ms 空闲结束。已有波特率保留；输入命令从原文明确给出的 ASCII 命令词生成稳定代码映射，不添加业务命令。

## 类型、单位与初始值

- 布尔接口使用设备目录规定的无量纲单位 `1`，错误的物理单位会被规范化并记录。
- 未指定启动状态时，布尔初值缺省 false，数值初值缺省 0；范围受限的串口整数初值使用范围内的值。常见的 0/1 与布尔表示按端口类型规范化。
- 明确写出的初始状态不被缺省值覆盖。未知字段、非法取值、校准缺失仍进入严格校验和修复反馈。
- 数值单位变化不被当成格式问题自动吞掉，例如原始 ADC 值与伏特之间仍需要 scale/offset 校准。

## 接入与追踪

实现位于 `app/services/configuration_policy.py`。接口规划和 supplied-contract API 使用同一解析与应用入口。SysML 提示采用配置决策对应的有效需求；原始需求保留在独立需求库存及配置记录中。

`run_current_comparison.py` 在三组方法调用之前统一解析配置，保存每题 `configuration_resolution.json`，向直接生成、直接反馈和工作流提供同样的有效需求。配置规则属于方法冻结文件，改变规则必须使用新的实验目录。

离线查看全部任务的配置决策：

```powershell
D:\software\python\python.exe experiment/code/prepare_configured_dataset.py
```

输出 `experiment/configured/configuration_v3/manifest.json` 与 `summary.json`。它们保留原划分、原始需求、已有公开解释、有效需求、决策和实现散列，不调用 LLM。导出器拒绝覆盖另一配置版本。

## 评测边界

修改配置后属于有记录的数据修订，不能与旧配置结果混合计分。独立功能测试和实物必须采用解析后的接线与协议；旧参考程序、隐藏测试或实际接线不一致时，须先更新对应夹具，不能将此类差异解释为算法失败或成功。

这是一套确定性硬件配置策略，不是通用自然语言需求求解器。多实例总线歧义、当前目录不支持的设备/协议以及不可满足的资源限制仍会报告错误。配置预处理完成不能证明生成代码功能正确，最终收益仍需新版本实验验证。
