## 具体修改

- **实际设备能力**：增加 DS1307 的 Unix 秒及有效性输入、一次性或周期读取；MPU6050 的加速度、角速度和原始 Y 轴输入；ILI9341 文本、数字、日期字段；单个和四位直驱数码管；TM1637 有限字形文本及滚动；动态串口格式、字符串、ISO 日期和命令载荷接收。驱动调用真实设备库，没有常量传感器替代。
- **接收与引脚校验**：显式串口接收校验统一使用注册表，消除新增日期/字符串接收器被旧的“仅命令或整数”规则拒绝的问题。字符串接收保留首尾空白；溢出帧整帧拒绝。配置解析识别英文 on/at/pin、DHT DATA= 接线与有颜色的 LED，避免已有明确引脚仍被填入另一个默认引脚。
- **模型与适配器边界**：语义审查获得注册驱动的初始化、采样、格式化和显示配置事实；SysML 保留状态、阈值、模式、时钟和业务定时。多蜂鸣器仅在契约明确互斥时复用硬件 tone 通道，切换时停止旧引脚。
- **SysML 追溯**：根据冻结需求 ID 补回遗漏的 requirement_text，减少模型重复输出长电路 JSON 导致的格式问题。追溯映射仍不是行为正确性的证明。
- **评测与反馈**：新测试由需求及公开条件生成，经过独立审查和参考程序预执行后冻结。实际编译诊断或运行反例反馈给契约/SysML。没有有效测试时保留可编译代码并标记未确认，避免空反馈反复重生成。
- **主机观察器**：GPIO 查询建立索引并使用二分查找，保持同时间戳最后一次写入的次序；检查窗口超过实际采集范围时标记未确认；数码管支持极性参数，无法可靠解码的扫描形态保留观察限制。公开测试协议补全已有 RTC/MPU 输入、LCD 元数据与数码管解码接口。

涉及代码主要位于 app/services/extended_devices.py、hardware_adapter.py、interface_registry.py、interface_planner.py、configuration_policy.py、serial_receiver.py、interface_semantics.py、sysml_semantic_review.py、sysml.py 和 experiment/code/behavior_full_*.py。

## 测试如何执行

代码先经官方 SysML 校验、IR/IL/C 确定性后端及硬件适配，再用真实 Arduino CLI 和设备库编译目标板程序。主机阶段以 g++ 编译同一候选的展开 C++，注入按钮电平、ADC、传感器读数、RTC 时间和串口帧，观察 GPIO、PWM、tone、Serial 与显示 API 的输出和时间。

21 个候选均保留模型、契约、目标板编译日志、测试输入、逐条断言结果与压缩轨迹。测试来源分为：11 题的方案经过独立模型审查、5 题使用明确标注的离线人工测试审查、5 题沿用历史定向补充计划的正向执行证据。历史补充计划存在格式要求过严等局限，相关审查意见保留；这些正向结果仅说明受测输入下的输出符合核心场景。三类证据不能合称统一的全需求独立测试。

离线人工测试中，串口屏幕移除了需求未规定的复位构造参数约束；时钟使用明确的 RTC 午夜跨日输入；孵化箱以实际采样产生的加热器动作作为越界计时锚点，检验 60 秒持续越界，避免假定 DHT 的采样相位。旧测试失败记录保留，没有据此改写旧分数。

测试是有限场景的主机 API 执行。它不证明像素显示、供电、真实器件、电气时序或全部 AVR 数值行为。本轮未新增 SimulIDE 电路仿真证据。孵化箱的五分钟通风、药盒的完整跨日状态等未覆盖功能已在计划中标注。

封存后从保存的 C++ 再次编译并重放全部 21 个候选，**21/21 通过**，未调用模型接口。最终专项回归共 **38 项通过**，另保留设备接线与语义审查专项日志。前端 TypeScript 检查通过。

## 公开条件与人工介入

原文、补全参数、引脚冲突处理与有效需求分别保存在每题 input.json 的 original_requirement、bench_completion、configuration_resolution 和 effective_requirement。延续此前授权的 250ms 默认响应上限，以及未规定周期的连续串口按钮状态每 500ms 至少一次报告；原文明确周期优先，持久显示内容不要求重复打印。

本地题中缺少的阈值、传感器换算、接线和串口协议作为开发实验条件逐题披露。另明确单个数码管计数溢出的显示方式、倒计日的整日取整规则、钢琴题文字与电阻属性矛盾的处理。串口屏幕的测试域是最多 63 字节的有限 ASCII 帧；日期串口接收域为 2000–2037 年。它们不代表对无界输入的支持。

模型接口中断后只进行离线处理。medium_018、串口屏幕和 advanced_018 使用中断前已经通过语义审查的确切模型恢复转换，重新校验并编译。medium_019 则显式手工编写两种显示模式的 SysML 控制器，经官方校验和同一确定性后端生成；没有伪装成自动模型调用成功，也没有手改生成的 C 内核。
